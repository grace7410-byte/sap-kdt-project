# MM (2026-08-06)

**러닝허브 서버**: S4550

## cf. 구매조직 - 컴퍼니코드 관계
- 하나의 회사코드와 연결된 **구매조직(=구매팀)**이 여러 플랜트를 관리할 수 있음
- **구매그룹**은 구매 담당자를 의미
- 회사 - 구매팀 - 구매 담당자(ex. 홍길동) 구조로 이해하면 됨
- 자재를 구매할 때는 반드시 구매 관련 조직 구조 정보가 데이터로 할당되어야 함

## 실습 절차

### `SU3` 유저 정보 관리 (User Profile)
- Parameter 탭에서 **BUK/EKG/EKO** = 회사코드/구매그룹/구매조직
- YCOA(Chart of Accounts), 기본 연도 등도 유저별 Default Parameter로 존재
- 기본값: 회사코드 1010, 구매조직 101C
- 구매그룹 **EKG**에 `Z##` 추가 → 이후 PIR/PO 등 EKG 기반 프로그램에서 기본값으로 자동 로딩됨

### `MD04` 자재별 재고/수요 목록
- MARA/MARC/MARD 같은 스탠다드 테이블을 사용자는 직접 조회하지 않고 MD04/MMBE 화면으로 조회
- 앞으로 트랜잭션 진행할 때마다 MD04를 계속 Refresh해서 PO Item/Stock 변화 확인

### `MMBE` 자재별 재고 현황
- 조직구조(회사코드/플랜트/저장위치) 기준 재고 현황 파악
- GR 입고 이후 Unrestricted use(가용재고) 수량 확인

cf. **SAP MM 핵심 프로세스**: PR → PO → GR → IR → IN
- 이번 프로젝트는 PR→PO 전환 대신 **PO부터 GR까지** 진행
- 트랜잭션 전, 마스터 데이터인 구매정보레코드(Info Record)를 먼저 생성해야 함

### `ME11` 구매정보레코드 생성 (PIR)
- 인포레코드 유형: 스탠다드 / 공급업체: `T-S52A##` / 자재: `ITR200-01` / 구매조직: `101C` / 플랜트: `1010`
- **Purch. Org. Data 1** 탭에서 `Standard Qty`, `Net Price` 입력 → 이후 PR/PO 생성 시 자동 제안
- 추가 설정: Minimum Qty(최소 구매 수량), Tol. Underdl./Overdl.(과소/과대 납품 허용 오차)
- **Texts** 탭: Info Memo에 "Hi", Purchase Order Text에 "Bye" 입력 후 저장

### `ME21N` 구매오더 생성 (PO)
- 공급업체 `T-S52A##` 입력 → 마스터 정보 자동 헤더 매핑
- Org. Data 탭에는 SU3에서 세팅한 유저 기본값이 자동 매핑됨
- 자재 `ITR200-01` 입력 시 유효 조건 기간에 맞는 info record 자동 로딩
- 🚨 **플랜트 입력 전까지는 인포 레코드 정보가 완전히 반영되지 않음**
  - [자재+공급업체]만 입력: General Data 레벨 → 단가/납기일/오차는 완전 결정 안 됨, 텍스트도 플랜트 무관 공통 영역만 로딩
  - [플랜트]까지 입력: Purch.Org/Plant Data 레벨 → 단가/조건/수량 완전 반영, 텍스트 재결정(Text Redetermination) 수행되어 Info Record PO text까지 복사됨
- 플랜트 `1010` 입력 → Delivery Address 자동 채움, Texts 탭에 "Bye" 확인
- 수량/날짜 입력 (당일 입고하려면 Delivery Date를 오늘 날짜로 반드시 변경) → 저장 후 문서번호 기억

🐛 확인 타임
- `ME22N`/`ME23N`으로 PO 수정/조회 가능 (상단 Purchase Order에서 Create ↔ Display/Change 전환)
- `MD04` Refresh: PO Item 생성 확인 (8/6 `10` Qty, 8/10 `500` Qty). Date는 PO 문서일이 아닌 **납품 예정일** 기준
- `MMBE` Refresh: On-Order Stock(`B`) = MD04의 PO Item 총수량, Unrestricted use(`A`) = MD04의 가용수량과 동일
- 다음 단계에서 On-Order Stock(`B`)을 Unrestricted use로 옮기는 것이 목표

### `MIGO` 자재문서 발행 - MM 입고
- PO 번호 입력 → 자동으로 PO 정보 매핑, My Purchase Order 목록에 추가
- Goods Receipt(`A01`) - Purchase Order(`R01`) = PO 기반 입고
- 이동유형 **101**: 참조문서(PO/생산오더) 기반 물리적 입고 처리
- Material 탭에서 매핑 확인, Quantity 탭에서 부분 입고 가능(수량 변경), Where 탭에서 플랜트+저장위치 필수 입력
- 모든 아이템 작성 완료 후 하단 **Item OK** 체크 → 저장 (체크 안 하면 에러 발생)

🐛 확인 타임 2
- `MMBE` Refresh: On-Order Stock(`B`)이 Unrestricted use로 이동, 재고는 `A`+`B`
- `MD04` Refresh: 재고 유형만 남고, MMBE 가용재고가 그대로 Stock으로 잡힘

### `FB03` 전표 조회
- (MM보다 FI 트랜잭션에 가깝지만, 입고 시 전표 자동 발행 확인용으로 포함)
- Document List에서 전표유형 `WE`, Posting Date 오늘로 조회
- 헤더: 회계전표번호/전기일/회사코드/회계연도 확인, Reference(참조문서번호)는 비어있음
- 아이템: 전기키(차 89/대 96), 계정(차 13300000/대 21120000), 금액/통화 확인
- 아이템 3개 이상인 경우: 구매 단가와 표준 단가가 다를 때 발생 (프로젝트 요구사항과 일치)
  - PRD 키 → 보고서 계정명 "가격차익/가격차손" = 실습화면 "Gain/Loss Prdn Variance" (동일 역할, 텍스트만 다름)

**Q. Reference 필드가 비었을 때 참조문서번호를 어떻게 알 수 있을까?**
- 아이템 더블클릭 → 문서/아이템번호/금액 확인 + 하단 **Purchasing Document** 번호 확인 가능
- 상단 **Display Document Header** → 팝업에서 **Reference Key**(참조문서번호+회계연도) 확인 가능
- `MIGO`에서 A01→A04(Display) 전환 시에도 자재문서/회계문서 함께 확인 가능
  - Doc. Info 탭 → FI Document 버튼 → FI 문서번호, Ledger 문서번호 확인

💡 8,9번은: 이동유형+평가클래스+트랜잭션키 조합으로 회계 전표 계정이 어떻게 자동으로 찾아 들어갔는지 역추적하는 과정

### `MM03` 자재마스터 조회
- 자재번호 입력 → View 선택 팝업에서 **Accounting 1** 탭
- 플랜트 입력 (저장위치는 불필요) → **Valuation Class**(평가클래스) 4자리 확인
- (원자재 3000, 반제품 7900 등 — 각자 자재의 평가클래스 기억해두기)

### `OBYC` 계정 매핑
- `BSX`(Inventory posting) 더블클릭 → Chart of Accounts는 YCOA 그대로
  - Valuation Class(7900) 행에서 매핑된 G/L Account(13300000)가 FB03 전표 1번 라인과 일치
  - Posting Key 버튼으로 차/대 전기키(차89/대99) 확인, FB03 전표 1번 라인과 일치
- `WRX`(GR/IR clearing account): 평가클래스 구분 없이 단일 계정(21120000)
  - FB03 전표 2번 라인과 일치, 전기키(차86/대96)도 일치
- `PRD`(Cost/price differences): 표준단가 vs PO단가 차이 시 발생
  - 차변(전기키83) - 계정 52070000(가격차손), 대변(전기키93) - 계정 52570000(가격차익)
  - FB03 전표 3,6번 라인과 일치 확인

💡 정리
- 1번째 입고 건(차손 세트): BSX(+500 재고), WRX(-1,000 GR/IR), PRD(+500 차변, 52070000)
- 2번째 입고 건(차익 세트): BSX(+500 재고), WRX(-100 GR/IR), PRD(-400 대변, 52570000)

## 💡 결론 / 인사이트
마스터 데이터(PIR) → PO → MIGO 입고 과정에서 발생한 물류 흐름이 OBYC의 계정 결정 규칙(BSX, WRX, PRD)을 거쳐 회계 전표로 자동 변환되는 **MM-FI 연동 구조**를 이해할 수 있었다.
