# SD (2026-08-07)

**러닝허브 서버**: S46000

## cf. SD란?
- **SD(Sales and Distribution)**: 기업의 영업, 수주, 출하, 납품, 수금에 이르는 영업/유통 전 과정을 통합 관리하는 SAP 핵심 모듈 (독일어 Vertrieb = 영업/판매유통)
- 표준 Order-to-Cash(O2C) 흐름과 판매영역 개념 이해 필요

## cf. SD T-Code 이해
- **V+A**: 오더(Auftrag) 관련 → `VA01`(생성)/`VA02`(변경)/`VA03`(조회)
- **V+L**: 출고(Lieferung) 관련 → `VL01N`/`VL02N`/`VL03N`
- **V+F**: 청구(Fakturierung) 관련 → `VF01`/`VF02`/`VF03`
- **V+K**: 조건/가격(Konditionen) 관련 → `VK11`/`VK12`
- T-Code 끝자리: 01=생성, 02=변경, 03=조회 (대부분)
- 순서: 마스터데이터 → 사전영업(선택) → 수주 → 출고 → 청구

**파트너 역할**: 본사가 주문(SP), 물류센터로 배송(SH), 본사 회계팀이 청구서 수령(BP), 본사 재무팀이 결제(PY) — 4개 역할이 전부 다른 회사/부서일 수 있음

**참고 T-Code 모음**
- 마스터 데이터: `XD01`(고객), `MM01`(자재), `VK11`(가격조건)
- 사전영업: `VA11`(문의), `VA21`(견적)
- 판매오더: `VA01`/`VA02`/`VA03`
- 출고: `VL01N`/`VL06O`(피킹리스트)/`VL02N`(PGI 처리)/`VL03N`
- 청구: `VF01`/`VF02`/`VF03`
- 회계 확인: `FB03`
- 기타: 반품 `VA01`(RE) → `VL01N`/`VL02N` → `VF01` / 미결주문 `CO06`,`V_RA` / 신용관리 `VKM1`,`FD32` / 판매오더유형 `VOV8` / 아이템카테고리 `VOV7` / 가격결정절차 `V/08`,`VK11` / Document Flow는 `VA03` 하단에서 추적

## 실습 절차

### `VK11` 가격 조건(Pricing) 생성
- 조건유형 **PR00**(기본가) 생성
- 팝업 옵션: Customer/material 조합 vs Price list/currency/material vs Material만(고객 무관) → **고객 구분 필요해서 Customer/material 선택**
- 영업조직 `1010`, 유통채널 `10`, 고객 `C620-A##`
- 아이템: 자재 `T-D1##`(오더수량 2, 무형자재), `P600-1##`(오더수량 5) — 금액은 각자 기억할 수 있는 값으로 입력
- 저장 후 Display 모드 확인 (`VK12`/`VK13`), Material 조회조건 `P600-1##` to `T-D1##`로 2개 동시 조회 가능

### `VA01` 판매오더(SO) 생성
- 오더유형 **OR**(표준), 판매조직 `1010`/유통채널 `10`/Division `00`으로 Sales Area 구성
- 1) Sold-to=Ship-to=`C620-A##`, 고객참조번호 `process##` → 아이템 입력 시 VK11에서 설정한 단가 자동 매핑
- 2) Sold-to `C620-A##` / Ship-to `C600-A##` (다르게 설정) → 여전히 단가 자동 매핑됨
- 3) 판매처에 다른 고객, 납품처에 620번 고객 → 전혀 다른 단가(100, 50)가 매핑됨 (매핑 조건이 다름을 확인)
- 납품요청일을 오늘로 변경 → 엔터 시 Sales Document로 이동
  - 경고 발생하지만, 헤더 날짜 변경이 기존 품목 Schedule Line에 자동 반영되지 않는다는 안내라 확인만 하고 진행

### `VL01N` 출하문서(Delivery) 생성
- SO 생성 후 진입하면 Order 필드에 자동으로 판매오더 번호 할당됨
- Shipping Point(출하지점) `1010` 입력 후 엔터
