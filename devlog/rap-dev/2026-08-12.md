#### 자재타입 SH ([`ZI_B07_MTART_F4`](../../reference/00_common-searchhelp.md))

**1) 텍스트 필드 매핑 (`_Text`)** — `I_MaterialType`의 `_Text` Association을 활용해 로그인 언어(`$session.system_language`) 기준 자재타입명(MaterialTypeName)을 1:1 매핑

```sql
@AbapCatalog.viewEnhancementCategory: [#NONE]
@AccessControl.authorizationCheck: #NOT_REQUIRED
@EndUserText.label: '자재타입'
@Metadata.ignorePropagatedAnnotations: true
define view entity ZI_B07_MTART_F4 as select from I_MaterialType
{
    key MaterialType,
    /* Associations */
    _Text[1: Language = $session.system_language].MaterialTypeName
}
```

Data Preview(F8) 확인: 영어/한국어 로그인 각각 텍스트 정상 노출 확인

**2) 드롭다운으로 구성** — Result Set Size를 `#XS`로 설정해 드롭다운 리스트 형태로 구성

```jsx
@ObjectModel.resultSet.sizeCategory: #XS
define view entity ZI_B07_MTART_F4 as select from I_MaterialType
{ // ...생략
}
```

**3) 자재유형 하드코딩 필터** — 현재 MARA에서 쓸 수 있는 유형(완제품/반제품/원자재/상품/부자재/포장재)만 조회되도록 필터링

    inner join   t001k as k on w.bwkey = k.bwkey
{
  key w.werks as Plant,
      w.name1 as PlantName,
      k.bukrs as CompanyCode
} where
  k.bukrs = 'K200'

### 4. 자재 관련 View 생성 ([보고서 01] 수행)

cf. RAP BO 계층 구조 개념 정리
- **기본 인터페이스/루트 뷰**: 네이밍에 i/ir 포함, Root는 `rootViewEntity`로 생성, 생성 후 불필요한 composition/association expose는 제거 (단, 이번 프로젝트는 부모-자식 관계를 정의해서 남겨둠)
- **Projection View**: 네이밍에 c/cr 포함, Projection View 폴더에서 별도 생성, `provider contract transactional_query` 필수, `define view` 사이에 `root` 키워드 추가, `@Metadata.allowExtensions: true` 어노테이션으로 Metadata Extension 생성 가능하게 함
- **Metadata Extension**: PV와 이름 동일하게 생성, element list에서 Ctrl+Shift로 필드 추가, 모든 필드에 `@UI.lineItem` 또는 `@UI.hidden: true` 어노테이션 필요
- **Service Definition**: PV에서 우클릭으로 생성
- **Service Binding**: 관련 오브젝트 모두 Active 확인 후 Binding도 Active + Publish

📌 자재 마스터 RAP BO 계층 구조

```
[ Data Model Layer ]                    [ Projection Layer ]
   ZR_B07_MARA (Root)      ───────►      ZC_B07_MARA (Root)
       │  ▲ composition/parent               │  ▲
       ▼  │ [0..*]                            ▼  │
   ZI_B07_MARATEXT (Child) ───────►      ZC_B07_MARATEXT (Child)
```

1. Interface/Root 계층: DB 기반으로 `ZI_(Child)` → `ZR_(Root)` 순서 생성, composition/association to parent 선언
2. Projection 계층: `ZC_(Child)` → `ZC_(Root)` 순서 생성, `redirected to` 적용, 정렬/필터 어노테이션 지정
3. Service 계층: Service Definition에서 두 Projection View 모두 expose

#### Interface BO View (`ZI_B07_MARATEXT`)
- 레퍼런스: `ZTB07MARA_T` 테이블
- View 생성 시 **"Define View Entity With To Parent Association"** 선택 (생성 후 코드 추가도 가능)

```jsx
association to parent ZR_B07_MARA as _Mara
    on $projection.MatUuid = _Mara.MatUuid
{
    key mat_uuid as MatUuid,
    key spras as Spras,
    maktx as Maktx,
    _Mara // Make association public
}
```

다시 `ZR_B07_MARA`로 돌아가 Child 뷰와 연결

```jsx
  composition [0..*] of ZI_B07_MARATEXT as _MaraText
  {
  // 생략(필드 전체)
  // 마지막 Association 파트에 추가
        _MaraText // Make association public
  }
```

#### Projection View (`ZC_B07_MARA`, `ZC_B07_MARATEXT`)

1. `ZC_B07_MARA` 생성 — Reference `ZR_B07_MARA`, Projection View로 생성
2. `root` 키워드 추가
3. 메타데이터/서치 허용 어노테이션 + Currency 연결

```jsx
@Metadata.allowExtensions: true
@Search.searchable: true
{
@Semantics.amount.currencyCode: 'Waers'
Stprs,
}
```

4. `ZC_B07_MARATEXT` 생성 — Reference `ZI_B07_MARA`(interface), Projection View로 생성
5. `provider contract transactional_query` 키워드 추가 (Root는 추가 안 함)

🐛 문제 — Redirect 필요성 발견
- `ZC_B07_MARATEXT`의 `_Mara` association이 같은 레벨의 `ZC_B07_MARA`가 아니라 Interface(Root) View인 `ZR_B07_MARA`를 그대로 가리키고 있음
- Projection은 Projection끼리, Interface는 Interface끼리 연결되어야 하는데 이게 깨진 상태
- 해결책: `_Mara` association을 Projection View 단으로 **리다이렉션(Redirect)** → **다음 날(8/13)에 이어서 진행**
