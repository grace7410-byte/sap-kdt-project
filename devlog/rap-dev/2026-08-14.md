#### 기본값 자동 설정 (Determination) 추가
- 신규 생성 시 기본값 세팅 (`On Modify` / Create): Waers='KRW', Peinh=1, Ersda=sy-datum
- 저장 직전 값 세팅 (`On Save` / Create): Matfi(변경금지)='X'
- Determination 이름: `SetInitialDefault`, `SetReadOnly`
- Ctrl+1 퀵픽스로 Handler Class(`LHC_ZR_B07_MARA`)에 메서드 2개 자동 생성

```
METHOD SetInitialDefault.
    MODIFY ENTITIES OF zr_b07_mara IN LOCAL MODE
    ENTITY zr_b07_mara
    UPDATE FIELDS ( Waers Peinh Ersda )
    WITH VALUE #( FOR key IN keys
                    ( %tky = key-%tky
                      Waers = 'KRW'
                      Peinh = 1
                      Ersda = sy-datum )
                ).
  ENDMETHOD.
```
```
METHOD SetReadOnly.
    MODIFY ENTITIES OF zr_b07_mara IN LOCAL MODE
    ENTITY zr_b07_mara
    UPDATE FIELDS ( Matfi )
    WITH VALUE #( FOR key IN keys
                    ( %tky = key-%tky
                      Matfi = 'X' )
                ).
  ENDMETHOD.
```

#### 유효성 검증 (Validation) 추가
1. 필수값 누락 체크 (플랜트, 저장위치, 자재타입, 평가클래스, 자재번호)
2. 자재코드(Matnr) 중복 체크 (이미 존재하는 자재인지 DB 조회)
3. 플랜트-저장위치 정합성 체크 (선택한 저장위치가 해당 플랜트에 존재하는지 T001L 등 조회)
4. 등록일자(Ersda) 범위 체크 (현재일 기준 한 달 이전까지만 허용)

#### Draft Action 준비 구문 연동 (Prepare)
- `draft determine action Prepare` 블록 안에 위 Validation들을 등록

#### ABAP Handler Class 구현 진행중

> Validation + Prepare + 내부 로직이 세트인데, 오늘은 2개(`CheckInit`, `CheckCreated`)만 하다 마무리. 남은 두 개는 다음으로.

## 오늘 배운 점 / 막힌 점
- Determination의 트리거 시점(`on modify` vs `on save`)에 따라 같은 목적의 로직도 다르게 동작한다는 걸 직접 비교하며 이해함
- Child 엔티티(Composition Child)는 MODIFY ENTITY 호출 시 자기 이름이 아니라 Parent와 연결된 alias로 호출해야 한다는 걸 처음 알게 됨 (아직 완전히 해결은 못함)
- Validation 로직은 이름만 정해두고 실제 구현까지는 시간이 부족해서 다음으로 넘김
