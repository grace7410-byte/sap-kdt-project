## 진행 내용

### [02] Behavior 설계

| 기능 | 구현 방식 | 상세 설명 |
| --- | --- | --- |
| Create | Managed | UUID는 `numbering : managed`로 자동 생성. 생성시 필수값: FI 계정타입, FI 계정번호. 변경시 계정번호는 수정 불가 |
| Update | Managed | etag 기반 낙관적 락(optimistic lock) 적용. 계정번호는 수정불가 |
| Delete | Managed | 관련 Text 레코드는 Composition으로 자동 연계 삭제 |

### CRUD 기능 구현 과정
1. `ZR_` 먼저 생성 → 관련 테이블(SKA1) 연결 + 넘버링(managed) 설정하면 Active 가능
2. etag용 타임스탬프 등 관리 필드는 모두 `readonly` 처리

cf. Concurrency Control 관련해서, MARA/SKA1 둘 다 관리 필드 추가하는 걸 깜빡했다는 걸 뒤늦게 발견해서 다시 챙겨서 추가함 (생성/변경 시 유저·타임스탬프 자동 기록은 반드시 Root/Interface View에 선언해야 함 — Projection은 UI 전달용이라 백엔드 자동 저장 로직이 안 돔)

3. 본격 조건 추가
   - 생성시 필수값: FI 계정타입, FI 계정번호 → `field ( mandatory : create ) Saknr, Glact;`
   - 계정번호는 변경 불가 → `field ( readonly : update ) Saknr;`
   - etag: `etag master ChangedAt`까지만 하면 됨 (`total etag`는 draft 지원할 때만 필요 — SKA1은 No Draft라 불필요)
   - Child(SKA1TEXT)에는 관리형 필드가 없어서 Parent에 의존한다고 명시: `etag dependent by _Ska1`
4. 클래스 생성 → Active
5. 매핑 완료
6. Text 필드 설정: `field ( readonly ) SakUuid; field ( mandatory : create, readonly : update ) Spras; field ( mandatory ) Saktx;`

### 여기까지 최종 코드

[`ZR_B07_SKA1`](../../reference/02_fi-account.md) BDEF(Root+Child) · [코드 보기](https://github.com/grace7410-byte/sap-kdt-project/blob/main/src/02_fi-account/bdef/ZR_B07_SKA1.bdef.asbdef)
```
managed implementation in class zbp_r_b07_ska1 unique;
strict ( 2 );

define behavior for ZR_B07_SKA1
persistent table ztb07ska1
lock master
authorization master ( instance )
etag master ChangedAt
{
  field ( numbering : managed, readonly ) SakUuid;
  field ( mandatory : create ) Saknr, Glact;
  field ( readonly : update ) Saknr;
  field ( readonly ) ChangedAt, ChangedBy, CreatedBy, CreationAt;

  create;
  update;
  delete;
  association _Ska1Text { create; }

  mapping for ztb07ska1 corresponding
    {
      ChangedAt    = changed_at;
      ChangedBy    = changed_by;
      CreatedBy    = created_by;
      CreationAt   = creation_at;
      SakUuid      = sak_uuid;
    }
}

define behavior for ZI_B07_SKA1TEXT
persistent table ztb07ska1_t
lock dependent by _Ska1
authorization dependent by _Ska1
etag dependent by _Ska1
{
  update;
  delete;
  field ( readonly ) SakUuid;
  field ( mandatory : create, readonly : update ) Spras;
  field ( mandatory ) Saktx;

  association _Ska1;

  mapping for ztb07ska1_t corresponding
    {
      SakUuid = sak_uuid;
      Saktx   = txt20;
    }
}
```

### MARA 문제 재확인

🐛 `get_instance_authorizations` 덤프 문제
- 아무것도 채우지 않고 그냥 리턴하면, 프레임워크가 "요청한 키에 대한 권한 결과가 없다"고 판단해서 `BEHAVIOR_CONTRACT_VIOLATION` 덤프를 던짐
```
METHOD get_instance_authorizations.
ENDMETHOD.
```
- 결국 Determination/Validation 쪽 문제로 되돌아옴 — 오늘 해결 못함

CRUD 기능 실제 구현 상태를 다시 표로 점검:

| 요구사항 | 상태 |
| --- | --- |
| 생성시 필수값 (플랜트/저장위치/자재타입/평가클래스/자재번호) | ✅ `field(mandatory:create)` |
| 기본값 자동설정 (통화 KRW, 가격단위 1, 생성일 현재일) | ✅ `SetInitialDefault` |
| 통화는 조회만 되게 설정 | ❌ 주석 처리되어 있음 |
| 저장시 필수값 체크 | ✅ `CheckInit` |
| 이미 존재하는 자재코드인 경우에도 체크 | ❌ `CheckMaterial` 메서드 비어있음 |
| 플랜트와 저장위치가 서로 관련 있는지 체크 | ❌ `CheckSLoc` 메서드 비어있음 |
| 등록일 한 달 이내 체크 | ✅ `CheckCreated` |
| 저장 전 matfi = 'X' | ✅ `SetReadOnly` |
| 추가로 기본값/체크로직 1개 이상 추가 | ❌ 미구현 |
