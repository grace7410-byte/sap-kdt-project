### [01] 자재 (MARA) — MARATEXT Spras Determination 재정리
이전에 수정한다 해놓고 안 했었던 부분. 자재명(MaraText) 생성 시 언어키(Spras)를 자동으로 채우는 로직을 다시 손봤다.

관련 오브젝트: [`ZR_B07_MARA`](../../reference/01_material-mgmt.md) · [코드 보기](../../src/01_material-mgmt/bimp/zbp_r_b07_mara.clas.abap)

#### 시도: SetLanguageDefault (Determination on modify)
```abap
define behavior for ZI_B07_MARATEXT alias MaraText
persistent table ztb07mara_t
draft table ztb07mara_td
lock dependent by _Mara
authorization dependent by _Mara
etag dependent by _Mara
{
  update;
  delete;

  field ( readonly ) MatUuid;
  field ( mandatory : create, readonly : update ) Spras;

  association _Mara{ with draft; }

  determination SetLanguageDefault on modify { create; }

  mapping for ztb07mara_t corresponding
  {
//    Maktx = maktx;
    MatUuid = mat_uuid;
//    Spras = spras;
  }
}
```
```abap
CLASS lhc_maratext DEFINITION INHERITING FROM cl_abap_behavior_handler.
  PRIVATE SECTION.
    METHODS SetLanguageDefault FOR DETERMINE ON MODIFY
      IMPORTING keys FOR MaraText~SetLanguageDefault.
ENDCLASS.

CLASS lhc_maratext IMPLEMENTATION.
  METHOD SetLanguageDefault.
    DATA lv_langu TYPE spras.
    TRY.
        lv_langu = cl_abap_context_info=>get_user_language_abap_format( ).
      CATCH cx_abap_context_info_error.
        lv_langu = sy-langu.
    ENDTRY.

    READ ENTITIES OF zr_b07_mara IN LOCAL MODE
      ENTITY MaraText
      FIELDS ( Spras )
      WITH CORRESPONDING #( keys )
      RESULT DATA(lt_text).

    DATA lt_update TYPE TABLE FOR UPDATE zi_b07_maratext.

    LOOP AT lt_text INTO DATA(ls_text) WHERE Spras IS INITIAL.
      APPEND VALUE #( %tky  = ls_text-%tky
                       Spras = lv_langu ) TO lt_update.
    ENDLOOP.

    IF lt_update IS NOT INITIAL.
      MODIFY ENTITIES OF zr_b07_mara IN LOCAL MODE
        ENTITY MaraText
          UPDATE FIELDS ( Spras )
          WITH lt_update
        REPORTED DATA(lt_reported)
        FAILED   DATA(lt_failed).
    ENDIF.
  ENDMETHOD.
ENDCLASS.
```

**적용 결과)** 원하는 바는 그냥 컨티뉴해도 자동으로 Spras 값이 들어가는 것이었는데, 실제로는 필수값이라서 무조건 선택을 해야 넘어감. 결론은 위 코드로는 실패.

🐛 문제
- `field ( mandatory : create, readonly : update ) Spras;`가 필수값으로 걸려 있어서, Determination이 값을 채우기 전에 화면에서 먼저 입력을 요구함. "Spras를 자동으로 채운다"는 목표 자체가 이 필드 제어 방식과 충돌.

✅ 해결
- 목표를 "Spras를 자동으로 채운다"가 아니라 "자재 생성 시 MaraText 자식 레코드 자체를 시스템이 자동으로 만들어준다"로 바꿔야 한다고 판단.
- 여기에 자재명(Maktx)을 필수값으로 설정해주면 기존 목표와 얼추 맞다고 보고, "자재 생성 시 자재명을 반드시 생성하도록 검증"하는 방향으로 전환.

```abap
field ( mandatory : create ) Maktx;
field ( mandatory : create, readonly : update ) Spras;

validation CheckMaraTextExist on save { create; }
```
```abap
CLASS lhc_maratext DEFINITION INHERITING FROM cl_abap_behavior_handler.
  PRIVATE SECTION.
    METHODS CheckMaraTextExist FOR VALIDATE ON SAVE
      IMPORTING keys FOR MaraText~CheckMaraTextExist.
ENDCLASS.

CLASS lhc_maratext IMPLEMENTATION.
  METHOD CheckMaraTextExist.
    READ ENTITIES OF zr_b07_mara IN LOCAL MODE
      ENTITY zr_b07_mara
      BY \_MaraText
      FIELDS ( Spras )
      WITH CORRESPONDING #( keys )
      RESULT DATA(lt_text)
      FAILED DATA(lt_failed_read).

    LOOP AT keys INTO DATA(ls_key).
      READ TABLE lt_text WITH KEY %tky-MatUuid = ls_key-%tky-MatUuid
        TRANSPORTING NO FIELDS.
      IF sy-subrc <> 0.
        APPEND VALUE #( %tky = ls_key-%tky ) TO failed-zr_b07_mara.
        APPEND VALUE #( %tky = ls_key-%tky
                         %msg = new_message( id = 'ZMSGE_B07'
                                              number = '015'
                                              v1 = 'Material Name'
                                              severity = if_abap_behv_message=>severity-error ) )
          TO reported-zr_b07_mara.
      ENDIF.
    ENDLOOP.
  ENDMETHOD.
ENDCLASS.
```
> 메시지 [`015`](../../src/message-class.md#015): "Field &1 is required and cannot be empty."

**결론:** 기존 Spras Determination(`SetLanguageDefault`) 로직은 없애고, `CheckMaraTextExist` Validation 로직을 추가하는 쪽으로 정리함.

> src 반영 상태: `zbp_r_b07_mara.clas.abap`에는 `SetLanguageDefault` 메서드 본문이 아직 남아있으나 bdef에서 determination 선언은 빠져 있고, `CheckMaraTextExist` validation은 bdef에 반영되어 있음. 다만 두 파일의 상단 변경이력 주석에는 아직 8/24 항목이 없음(마지막 기록이 8/21) — 헤더 갱신이 필요하면 별도로 주석만 전달하겠음.

### [04] 회계계정결정 — 전기키(Bschl)/차대변(Shkzg) 서치헬프 및 매핑 로직
관련 오브젝트: [`ZR_B07_T030`](../../reference/04_account-determination.md) · [코드 보기](../../src/04_account-determination/cds/ZR_B07_T030.ddls.asddls)

- 전기키 서치헬프 신규 생성: [`ZI_B07_BSCHL_F4`](../../reference/00_common-searchhelp.md) · [코드 보기](../../src/00_common-searchhelp/cds/ZI_B07_BSCHL_F4.ddls.asddls)
- 차변/대변 서치헬프 신규 생성: [`ZI_B07_SHKZG_F4`](../../reference/00_common-searchhelp.md) · [코드 보기](../../src/00_common-searchhelp/cds/ZI_B07_SHKZG_F4.ddls.asddls)
- 기존 Projection View(`ZC_B07_T030`)에 두 서치헬프 연결 완료

전기키 → 차/대변 자동 매핑 로직을 어떻게 짤지 고민함. 후보는 두 가지였다.
1. 89, 96 등의 전기키 → 차/대변을 결정해주는 테이블을 따로 구성
2. 또는 여러 interface view의 조합으로 결정

**시도한 방식(2번 변형): 매핑 전용 Interface View + Association**
- `I_DomainFixedValueText`를 소스로 `ZDB07BSCHL` 도메인만 필터링한 매핑 전용 Interface View(`zi_b07_debit_credit`)를 별도로 새로 팜(기존 `ZI_B07_BSCHL_F4`는 순수 F4용이라 건드리지 않고 분리).
- 이 매핑 뷰를 Root BO(`ZR_B07_T030`)에 Association(`_ShkzgLookup`)으로 연결.
- Behavior에서는 `Determine on modify(field Bschl)`로 전기키 입력 즉시 트리거되게 구성해서, 이 association을 통해 값을 읽어와 Shkzg 필드에 세팅하려고 시도.

```abap

      @UI.hidden: true
```

🐛 문제
- 앞선 view(`zi_b07_debit_credit`)를 활용하는 방식으로 메소드를 짰는데 안 먹음.

✅ 해결
- `zi_b07_debit_credit` 없다 치고 처음부터 dd07t를 직접 조회하는 방식으로 다시 구성.

```abap
METHOD SetShkzg.
  DATA: lt_update TYPE TABLE FOR UPDATE zr_b07_t030.

  READ ENTITIES OF zr_b07_t030 IN LOCAL MODE
       ENTITY zr_b07_t030
         FIELDS ( Bschl )
         WITH CORRESPONDING #( keys )
       RESULT DATA(lt_bschl).

  DELETE lt_bschl WHERE Bschl IS INITIAL.
  CHECK lt_bschl IS NOT INITIAL.

  LOOP AT lt_bschl ASSIGNING FIELD-SYMBOL(<fs_bschl>).
    SELECT SINGLE ddtext
      FROM dd07t
      WHERE domname     = 'ZDB07BSCHL'
        AND domvalue_l  = @<fs_bschl>-Bschl
        AND ddlanguage  = @sy-langu
      INTO @DATA(lv_shkzg).

    IF sy-subrc = 0.
      APPEND VALUE #( %tky  = <fs_bschl>-%tky
                       Shkzg = lv_shkzg ) TO lt_update.
    ENDIF.
  ENDLOOP.

  IF lt_update IS NOT INITIAL.
    MODIFY ENTITIES OF zr_b07_t030 IN LOCAL MODE
      ENTITY zr_b07_t030
        UPDATE FIELDS ( Shkzg )
        WITH lt_update.
  ENDIF.
ENDMETHOD.
```

처음부터 이 코드만 있으면 되는 거였음.

관련 구현: [`ZBP_R_B07_T030`](../../reference/04_account-determination.md) · [코드 보기](../../src/04_account-determination/bimp/zbp_r_b07_t030.clas.abap)

지금은 저장할 때 자동 매핑되는 것까지 되어있는데, 이제는 `@Consumption.valueHelpDefinition`의 `additionalBinding` 기능을 활용해서 F4 팝업에서 행을 선택하는 순간 그 행의 다른 컬럼 값을 화면의 다른 필드에 자동으로 꽂아주는 기능을 적용해야 함(미리 텍스트로 뽑아놓은 코드 보면서 마저 작성해서 적용하기).
