## 진행 내용

### [02] FI계정관리

#### 피드백 해결: 계정번호 중복 체크 (`CheckDuplicate` 신규)
중복된 계정이 생성되는 문제. `saknr`은 테이블 정의상 `ZEB07SAKNR`(UNIQUE 인덱스)로 되어 있지만, PK 자체는 UUID뿐이라 별도 체크 로직이 없으면 값이 있기만 하면 그대로 저장됨을 확인. `validation`으로 중복 체크를 구현하기로 함.

관련 오브젝트: [`ZR_B07_SKA1`](../../reference/02_fi-account.md) BDEF · [코드 보기](../../src/02_fi-account/bdef/ZR_B07_SKA1.bdef.asbdef)
```abap
validation CheckDuplicate on save { create; field Saknr; }
```

처음에는 T030의 `CheckAccountExist`를 참고해 작성했는데 루프 안에서 셀렉트하는 방식이 거슬려서 셀렉트 → 루프 → read 구조로 변경. 그 과정에서 `reported`/`failed`를 각각 채우는 위치(성공 시가 아니라 값을 찾은 그 시점)를 반대로 써서 `No component exists with the name "%ELEMENT-SAKNR"` 오류를 겪었으나, 원인은 단순히 코드를 옮겨적을 때 다른 코드를 잘못 베낀 것이었음.

[구현 클래스](../../reference/02_fi-account.md) · [코드 보기](../../src/02_fi-account/bimp/zbp_r_b07_ska1.clas.abap)
```abap
METHOD CheckDuplicate.
  READ ENTITIES OF zr_b07_ska1 IN LOCAL MODE
    ENTITY zr_b07_ska1
    FIELDS ( Saknr ) WITH CORRESPONDING #( keys )
    RESULT DATA(lt_ska1).
  SELECT saknr FROM ztb07ska1
      INTO TABLE @DATA(lt_db_saknr). " 중복 확인할 테이블을 미리 담아두기
  LOOP AT lt_ska1 INTO DATA(ls_ska1).
    READ TABLE lt_db_saknr INTO DATA(lv_db_saknr) WITH KEY saknr = ls_ska1-Saknr.
    IF sy-subrc = 0.
      APPEND VALUE #( %tky = ls_ska1-%tky ) TO failed-zr_b07_ska1.
      APPEND VALUE #(   %tky = ls_ska1-%tky
                        %element-Saknr = if_abap_behv=>mk-on
                        %msg = new_message(
                                  id       = 'ZMSGE_B07'
                                  number   = '017'
                                  v1       = 'Account'
                                  v2 = ls_ska1-Saknr
                                  severity = if_abap_behv_message=>severity-error )
                      ) TO reported-zr_b07_ska1.
    ENDIF.
  ENDLOOP.
ENDMETHOD.
```

#### 피드백 - 필수 아니라 패스
"입력 안 해도 저장됨"(Bukrs/Waers/Mitkz mandatory 미지정) 이슈는, FS 2.1 필드 정의상 이 세 필드가 원래 필수값으로 명시되지 않았던 점을 확인하고 그대로 두기로 함.

#### 피드백 해결: 회사코드/통화/조정계정유형 존재 여부 검증 (`CheckExist` 신규)
Value Help(F4)를 걸어도 사용자가 직접 문자열을 타이핑해서 넣는 경우까지는 막지 못한다는 걸 확인. F4로 연결된 값이 실제 존재하는 값인지 검증하는 로직이 별도로 필요함을 깨달음.

관련 오브젝트: [`ZR_B07_SKA1`](../../reference/02_fi-account.md) BDEF · [코드 보기](../../src/02_fi-account/bdef/ZR_B07_SKA1.bdef.asbdef)
```abap
validation CheckExist on save { create; update; field Bukrs, Waers, Mitkz; }
```

create뿐 아니라 update 시에도 체크해야 함(Saknr과 달리 이 세 필드는 수정 가능). [구현 클래스](../../reference/02_fi-account.md) · [코드 보기](../../src/02_fi-account/bimp/zbp_r_b07_ska1.clas.abap)에서 3개 필드를 한 번에 READ한 뒤 필드별로 개별 IF문으로 검증하도록 구성.

처음에는 `READ TABLE ... INTO DATA(lv_db_bukrs)`로 값을 읽어와 `IS INITIAL`로 판단했는데, 실제로는 읽어온 값을 이후 로직에서 쓰지 않아 변수가 미사용 상태로 남는 문제가 있었음. `TRANSPORTING NO FIELDS`로 바꿔 레코드 존재 여부만 확인하고, 판단 기준도 표준 방식인 `sy-subrc <> 0`으로 정리한 최종본:

```abap
METHOD CheckExist.
  READ ENTITIES OF zr_b07_ska1 IN LOCAL MODE
    ENTITY zr_b07_ska1
    FIELDS ( Bukrs Waers Mitkz ) WITH CORRESPONDING #( keys )
    RESULT DATA(lt_ska1).

  SELECT bukrs FROM t001
      INTO TABLE @DATA(lt_db_bukrs). " T001에 담긴 회사코드인지 확인할 용도로 미리 조회 (K200)
  SELECT waers FROM tcurc
      INTO TABLE @DATA(lt_db_waers). " 마찬가지로 원본 테이블 tcurc 데이터 확인용으로 미리 조회
  SELECT mitkz FROM zi_b07_mitkz_f4
      INTO TABLE @DATA(lt_db_mitkz). " 직접 만든 서치헬프용으로 5개 값만 미리 담기

  LOOP AT lt_ska1 INTO DATA(ls_ska1).
    READ TABLE lt_db_bukrs TRANSPORTING NO FIELDS WITH KEY bukrs = ls_ska1-Bukrs.
    IF sy-subrc <> 0 AND ls_ska1-Bukrs IS NOT INITIAL. " 회사코드를 입력한 경우에만 값 검증!
      APPEND VALUE #( %tky = ls_ska1-%tky ) TO failed-zr_b07_ska1.
      APPEND VALUE #(   %tky = ls_ska1-%tky
                        %element-Bukrs = if_abap_behv=>mk-on
                        %msg = new_message(
                                  id       = 'ZMSGE_B07'
                                  number   = '019'
                                  v1       = 'Company Code'
                                  v2 = ls_ska1-Bukrs
                                  severity = if_abap_behv_message=>severity-error )
                      ) TO reported-zr_b07_ska1.
    ENDIF.

    READ TABLE lt_db_waers TRANSPORTING NO FIELDS WITH KEY waers = ls_ska1-Waers.
    IF sy-subrc <> 0 AND ls_ska1-Waers IS NOT INITIAL. " 통화키를 입력한 경우에만 값 검증!
      APPEND VALUE #( %tky = ls_ska1-%tky ) TO failed-zr_b07_ska1.
      APPEND VALUE #(   %tky = ls_ska1-%tky
                        %element-Waers = if_abap_behv=>mk-on
                        %msg = new_message(
                                  id       = 'ZMSGE_B07'
                                  number   = '019'
                                  v1       = 'Currency'
                                  v2 = ls_ska1-Waers
                                  severity = if_abap_behv_message=>severity-error )
                      ) TO reported-zr_b07_ska1.
    ENDIF.

    READ TABLE lt_db_mitkz TRANSPORTING NO FIELDS WITH KEY mitkz = ls_ska1-Mitkz.
    IF sy-subrc <> 0 AND ls_ska1-Mitkz IS NOT INITIAL. " 값을 입력한 경우에만 검증할 수 있도록 하기!
      APPEND VALUE #( %tky = ls_ska1-%tky ) TO failed-zr_b07_ska1.
      APPEND VALUE #(   %tky = ls_ska1-%tky
                        %element-Mitkz = if_abap_behv=>mk-on
                        %msg = new_message(
                                  id       = 'ZMSGE_B07'
                                  number   = '019'
                                  v1       = 'Reconciliation Account Type'
                                  v2 = ls_ska1-Mitkz
                                  severity = if_abap_behv_message=>severity-error )
                      ) TO reported-zr_b07_ska1.
    ENDIF.
  ENDLOOP.
ENDMETHOD.
```

> 메시지 [`019`](../../src/message-class.md#019)

🧪 테스트: 회사코드/통화/조정계정유형 각각 이상한 값을 넣었을 때 해당 필드만 개별로 에러가 뜨고, 값이 비어있으면(입력 안 한 경우) 검증을 건너뛰는 것 확인. 2개 이상 동시에 틀려도 각각 잘 잡아냄.

cf. `zi_b07_mitkz_f4`처럼 원본 테이블이 아니라 뷰에서 값을 조회한 경우, 조회 대상 뷰의 필드명(`mitkz`)에 맞춰 SELECT 절 필드명을 정확히 맞춰줘야 함을 다시 확인.

#### 피드백 해결: 신규 생성 시 거래종료(Loevm) 편집 불가 처리
신규 벤더를 만들자마자 "거래 종료"로 체크할 수 있는 게 로직상 이상하다는 피드백. MARA 때 만든 `get_instance_features` 패턴을 참고해서, 생성 시에는 `Loevm`을 회색(read only) 처리하고 수정(Update) 시에만 편집 가능하도록 Feature Control로 구현.

관련 오브젝트: [`ZR_B07_LFA1`](../../reference/03_vendor.md) BDEF · [코드 보기](../../src/03_vendor/bdef/ZR_B07_LFA1.bdef.asbdef)
```abap
field ( features : instance ) Loevm;
```

[구현 클래스](../../reference/03_vendor.md) · [코드 보기](../../src/03_vendor/bimp/zbp_r_b07_lfa1.clas.abap)
```abap
METHOD get_instance_features.
  DATA lt_result TYPE TABLE FOR FEATURES RESULT zr_b07_lfa1.
  READ ENTITIES OF zr_b07_lfa1 IN LOCAL MODE
    ENTITY zr_b07_lfa1
    FIELDS ( LifUuid )
    WITH CORRESPONDING #( keys )
    RESULT DATA(lt_lfa1).
  SELECT lif_uuid FROM ztb07lfa1
      INTO TABLE @DATA(lt_dummy)." 미리 DB 테이블 데이터를 받아놓고
  LOOP AT lt_lfa1 INTO DATA(ls_lfa1). " Uuid(=PK) 기준으로 겹치는 데이터가 있다면 기존 벤더 수정중!
  READ TABLE lt_dummy INTO DATA(lv_dummy) WITH KEY lif_uuid = ls_lfa1-LifUuid.
    " 조회 성공 = 기존 벤더(Update) = 거래종료 편집 가능
    " 조회 실패 = 신규 생성 중(Create) = 거래종료 readonly
    DATA(lv_readonly) = COND #( WHEN sy-subrc = 0
                                 THEN if_abap_behv=>fc-f-unrestricted
                                 ELSE if_abap_behv=>fc-f-read_only ).
    APPEND VALUE #( %tky         = ls_lfa1-%tky
                     %field-Loevm = lv_readonly ) TO lt_result.
  ENDLOOP.
  result = lt_result.
ENDMETHOD.
```

🧪 테스트: Edit(수정)으로 들어갔을 땐 체크박스가 열려있고, 새로 Create한 경우엔 회색(선택 불가)으로 나오는 것 확인.

#### 피드백 - 필수 아니라 패스
Akont/Ekorg,Ekgrp/Minbw 필수값 미체크 이슈는, 대부분 필수로 두는 게 좋다는 판단은 서지만 시간 관계상 보류.

### [04] 회계계정결정관리

#### 피드백 해결: 자재평가/전기키/차대변/회계결정코드 존재 여부 검증 (`CheckExist` 신규)
[02]의 `2-3`과 동일한 패턴. 다만 이 4개 필드는 원본 테이블이 아니라 값 일부만 담긴 서치헬프 뷰에서 조회하는 게 맞다고 판단해 `ZI_B07_BKLAS_F4`/`ZI_B07_BSCHL_F4`/`ZI_B07_SHKZG_F4`/`ZI_B07_KTOSL_F4`에서 조회. `Ktosl`(회계결정코드)은 강사님이 별도로 언급하진 않았지만, 계정 검증도 이미 하고 있는 김에 트랜잭션키도 함께 체크하는 게 맞다고 판단해 추가.

관련 오브젝트: [`ZR_B07_T030`](../../reference/04_account-determination.md) BDEF · [코드 보기](../../src/04_account-determination/bdef/ZR_B07_T030.bdef.asbdef)
```abap
validation CheckExist on save { create; update; field Bklas, Bschl, Shkzg, Ktosl; }
```

#### 피드백 해결: 자재평가/전기키/차대변 미입력 저장 문제도 같이 처리
차/대는 전기키 입력 시 자동으로 채워지긴 하지만, 자동 입력된 값도 사용자가 지울 수 있으므로 결국 모든 필드를 다 검증하는 게 맞다고 판단. 처음엔 `CheckEmpty`로 이름을 따로 만들려다가, 필드 검증 로직 자체가 겹쳐서 그냥 위 `CheckExist` 안에서 같이 처리하기로 함(존재 여부 체크 앞에 필수값 체크를 추가).

[구현 클래스](../../reference/04_account-determination.md) · [코드 보기](../../src/04_account-determination/bimp/zbp_r_b07_t030.clas.abap)
```abap
METHOD CheckExist.
  READ ENTITIES OF zr_b07_t030 IN LOCAL MODE
    ENTITY zr_b07_t030
    FIELDS ( Bklas Bschl Shkzg Ktosl ) WITH CORRESPONDING #( keys )
    RESULT DATA(lt_t030).
  SELECT bklas FROM zi_b07_bklas_f4
      INTO TABLE @DATA(lt_db_bklas). " 직접 만든 서치헬프용으로 4개 값만 미리 담기
  SELECT bschl FROM zi_b07_bschl_f4
      INTO TABLE @DATA(lt_db_bschl). " 직접 만든 서치헬프용으로 10개 값만 미리 담기
  SELECT shkzg FROM zi_b07_shkzg_f4
      INTO TABLE @DATA(lt_db_shkzg). " 직접 만든 서치헬프용으로 2개 값만 미리 담기
  SELECT ktosl FROM zi_b07_ktosl_f4
      INTO TABLE @DATA(lt_db_ktosl). " 직접 만든 서치헬프용으로 10개 값만 미리 담기
  LOOP AT lt_t030 INTO DATA(ls_t030).
    IF ls_t030-Bklas IS INITIAL.
      APPEND VALUE #( %tky = ls_t030-%tky ) TO failed-zr_b07_t030.
      APPEND VALUE #( %tky = ls_t030-%tky
                    %element-Bklas = if_abap_behv=>mk-on
                    %msg = new_message( id = 'ZMSGE_B07' number = '015' v1 = 'Valuation Class'
                                        severity = if_abap_behv_message=>severity-error ) )
        TO reported-zr_b07_t030.
    ENDIF.
    IF ls_t030-Bschl IS INITIAL.
      APPEND VALUE #( %tky = ls_t030-%tky ) TO failed-zr_b07_t030.
      APPEND VALUE #( %tky = ls_t030-%tky
                    %element-Bschl = if_abap_behv=>mk-on
                    %msg = new_message( id = 'ZMSGE_B07' number = '015' v1 = 'Posting Key'
                                        severity = if_abap_behv_message=>severity-error ) )
        TO reported-zr_b07_t030.
    ENDIF.
    IF ls_t030-Shkzg IS INITIAL. " 값을 입력한 경우에만 검증할 수 있도록 하기!
      APPEND VALUE #( %tky = ls_t030-%tky ) TO failed-zr_b07_t030.
```

#### 피드백 해결: 중복 데이터 생성 방지 (`CheckDuplicate` 신규)
`Seqnr`이 Key라서 매번 새 값(max+1)으로 채번되기 때문에, 완전히 똑같은 조합(이동유형+회계결정코드+평가클래스+계정)이 이미 있어도 시스템이 "새 레코드"로 인식해서 그냥 저장되는 문제.

관련 오브젝트: [`ZR_B07_T030`](../../reference/04_account-determination.md) BDEF · [코드 보기](../../src/04_account-determination/bdef/ZR_B07_T030.bdef.asbdef)

```abap
validation CheckDuplicate on save { create; update; field Bwart, Ktosl, Bklas, Saknr; }
```

[구현 클래스](../../reference/04_account-determination.md) · [코드 보기](../../src/04_account-determination/bimp/zbp_r_b07_t030.clas.abap)
```abap
METHOD CheckDuplicate.
  READ ENTITIES OF zr_b07_t030 IN LOCAL MODE
    ENTITY zr_b07_t030
      FIELDS ( Bwart Ktosl Bklas Saknr )
      WITH CORRESPONDING #( keys )
    RESULT DATA(lt_t030).

  SELECT map_uuid, bwart, ktosl, bklas, saknr FROM ztb07t030
    INTO TABLE @DATA(lt_db_data).

  LOOP AT lt_t030 INTO DATA(ls_t030)
       WHERE Bwart IS NOT INITIAL AND Ktosl IS NOT INITIAL
         AND Bklas IS NOT INITIAL AND Saknr IS NOT INITIAL.

    DATA(lv_is_dup) = abap_false.

    LOOP AT lt_db_data INTO DATA(ls_db_data)
         WHERE bwart    = ls_t030-Bwart
           AND ktosl    = ls_t030-Ktosl
           AND bklas    = ls_t030-Bklas
           AND saknr    = ls_t030-Saknr
           AND map_uuid <> ls_t030-MapUuid.

      lv_is_dup = abap_true.
      EXIT.
    ENDLOOP.

    IF lv_is_dup = abap_true.
      APPEND VALUE #( %tky = ls_t030-%tky ) TO failed-zr_b07_t030.
      APPEND VALUE #( %tky = ls_t030-%tky
                       %msg = new_message( id = 'ZMSGE_B07'
                                            number   = '017'
                                            v1       = 'Account Determination'
                                            v2       = |{ ls_t030-Bwart }/{ ls_t030-Ktosl }/{ ls_t030-Bklas }|
                                            severity = if_abap_behv_message=>severity-error ) )
        TO reported-zr_b07_t030.
    ENDIF.
  ENDLOOP.
ENDMETHOD.
```
