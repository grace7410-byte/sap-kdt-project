## 4. CRUD 기능 + Draft

### `ZR_B07_EINA` Behavior Definition (Managed) — [코드 보기](../../src/05_purchase-info/bdef/ZR_B07_EINA.bdef.asbdef)
`persistent table ztb07eina`, `etag master LocChangedAt`로 기본 골격 설정 후 퀵픽스로 `zbp_r_b07_eina` 클래스 생성.

`ZC_B07_EINA`/`ZC_B07_EINE` Projection Behavior Definition도 함께 생성 — [코드 보기](../../src/05_purchase-info/bdef/ZC_B07_EINA.bdef.asbdef)
```abap
define behavior for ZC_B07_EINA
{
  use create; use update; use delete;
  use association _Eine { create; }
}
define behavior for ZC_B07_EINE
{
  use update; use delete;
  use association _Eina;
}
```

**UUID/Draft 기본 설정**: `field ( numbering : managed, readonly ) InfUuid;`를 헤더에 걸면 아이템(Eine) 쪽에는 자동으로 `field ( readonly ) InfUuid;`가 적용됨. 아이템은 부모 ETag를 그대로 상속받는 구조라 `etag master <field>` 대신 `etag dependent by _Eina`로 지정.

이 과정에서 활성화 에러가 하나 발생 — "자식 엔티티가 부모(etag master) 엔티티와 동일한 필드명(LOCCHANGEDAT)을 가질 수 없다"는 메시지였다. 처음엔 FS 필드 정의서에 `loc_changed_at`이 없길래 단순 누락이라 판단해서 8/27에 임의로 추가했었는데, 알고 보니 **아이템이 부모 ETag를 dependent로 상속받는 구조라 자기만의 `loc_changed_at`을 별도로 가지면 안 되는 게 설계상 맞았던 것**이었다. `created_at`~`changed_by`는 아이템에도 그대로 있지만 `loc_changed_at`만 없는 게 FS의 의도였던 셈. 테이블(`ztb07eine`)은 `include zsb07timestamp`를 그대로 쓰되, CDS View 단(`ZI_B07_EINE`, `ZC_B07_EINE`)과 MDE(`ZC_B07_EINE`)에서 `LocChangedAt` 노출만 제거.

Draft 설정(`with draft`, `draft table`, `draft action Edit/Activate/Resume/Discard`, `draft determine action Prepare`, `total etag ChangedAt`)과 Mapping까지 반영. 아이템은 `zi_b07_eine alias Eine`로 alias를 걸어두었다(뒤에서 Root 경유 접근에 사용).

### 헤더 요구사항 구현
- 구매정보레코드 번호(Infnr): "생성시 필수값 표시 없이 validation에서만 체크" + "수정 불가" → `field ( readonly : update ) Infnr;`
- `determination SetDefaults on modify { create; }`, `determination SetInfnrNumber on save { create; }`
- `validation CheckRequired on save { create; update; }`
- `validation CheckDuplicate on save { create; update; field LifUuid, MatUuid; }`
- `validation CheckEsokz on save { create; update; field Esokz; }`

[구현 클래스](../../reference/05_purchase-info.md) · [코드 보기](../../src/05_purchase-info/bimp/zbp_r_b07_eina.clas.abap) — `SetDefaults`(Esokz 기본값 '0', Ekorg/Ekgrp를 공급업체 기준으로 자동 설정), `SetInfnrNumber`(`NUMBER_GET_NEXT`, 연도 4자리+뒤 6자리로 구성), `CheckRequired`(LifUuid/MatUuid/Meins 필수), `CheckDuplicate`(공급업체+자재 조합 중복 체크), `CheckEsokz`(현재는 '0' 외 값이면 에러) 구현.

### 아이템 요구사항 구현
- 플랜트(Werks): "생성시 필수, 입력 팝업" + "수정 불가" → `field ( mandatory : create, readonly : update ) Werks;`
- 통화(Waers): "기본값 'KRW' + Read Only" → `field ( readonly ) Waers;`
- `determination SetItemDefaults on modify { create; }`
- `validation CheckExist on save { create; update; field Werks; }`
- `validation CheckPositive on save { create; update; field Peinh; }`

MARA/MaraText 때와 동일하게, `zi_b07_eine`은 Root가 아니라 Composition Child(`lock dependent by _Eina`)라서 `ENTITY zi_b07_eine`으로 직접 접근이 안 되고, Root(`zr_b07_eina`)를 거쳐 `BY \_Eine`으로 우회 접근해야 함. BDEF에 `alias Eine`을 걸어두고, `READ/MODIFY ENTITIES OF zr_b07_eina ... BY \_Eine`로 해결.

`SetItemDefaults`(Waers='KRW', Prdat='99991231' 기본값), `CheckExist`(Werks가 `ZI_B07_WERKS_F4`에 존재하는 플랜트인지 검증), `CheckPositive`(Peinh가 0 이하면 에러) 구현.
