## 진행 내용

### Waers Readonly 오류 — Feature Control로 전환
화면 띄우자마자 Waers(통화) 필드에서 에러 발생:
```
A static read-only field 'WAERS' is not allowed for an editable amount field
```
전에 자재마스터(MARA) `Stprs`(표준가격)에서 겪었던 것과 똑같은 원인이었음. `Stprs`에 `@Semantics.amount.currencyCode: 'Waers'` 어노테이션이 붙어있어서 `Stprs` 자체가 편집 가능한 필드로 취급되는데, BDEF에서 `field(readonly) Waers`처럼 정적으로 고정해버리면 모순이 생김. 그때 해결법 그대로 적용.

관련 오브젝트: [`ZR_B07_EINA`](../../reference/05_purchase-info.md) BDEF · [코드 보기](../../src/05_purchase-info/bdef/ZR_B07_EINA.bdef.asbdef)
```abap
// field ( readonly ) Waers; // 정적 제어라 에러남
field ( features : instance ) Waers;
```

퀵 픽스로 메소드 골격을 만들려고 했는데 이번엔 안 먹어서 직접 작성. 근데 여기서부터 여러 문법 오류를 순서대로 만남.

🐛 문제 1: `get_instance_features`를 아이템(`zi_b07_eine`)에 바로 못 씀 — `ENTITY zi_b07_eine`로 직접 참조하는 것 자체가 불가능함(Composition Child이기 때문). MaraText 때 이미 겪었던 것과 동일한 제약.
✅ 해결: BDEF에 `alias Eine`가 이미 있었으므로(8/30에 CheckExist/CheckPositive 만들 때 적용), 동일하게 Root를 거쳐 `BY \_Eine`로 우회 조회.

🐛 문제 2: `%element`/`failed`/`reported`를 Root(`zr_b07_eina`) 기준으로 쓰면 Werks/Peinh 같은 아이템 전용 필드는 타입이 안 맞음.
✅ 해결: `failed-eine`/`reported-eine`처럼 Child(alias `Eine`) 기준으로 수정.

🐛 문제 3: `FOR zi_b07_eine~...`처럼 기술명으로 계속 쓰다가 오류. `alias Eine`를 선언했으면 전부 `FOR eine~...`로 통일해야 함.
✅ 해결: 전체 통일.

최종 코드: [구현 클래스](../../reference/05_purchase-info.md) · [코드 보기](../../src/05_purchase-info/bimp/zbp_r_b07_eina.clas.abap)
```abap
METHOD get_instance_features.
  READ ENTITIES OF zr_b07_eina IN LOCAL MODE
    ENTITY zr_b07_eina
    BY \_Eine
    FIELDS ( Werks )
    WITH CORRESPONDING #( keys )
    RESULT DATA(lt_eine).

  result = VALUE #( FOR ls_eine IN lt_eine
                      ( %tky         = ls_eine-%tky
                        %field-Waers = if_abap_behv=>fc-f-read_only ) ).
ENDMETHOD.
```
화면에서는 완전히 텍스트로만 나오는 정적 readonly(`field(readonly)`)와 다르게, 입력창(Input box) 형태는 유지되면서 편집만 막힌 상태로 렌더링됨.

### Prepare 액션 설계 문제
`CheckExist`/`CheckPositive`를 Root의 `Prepare`에 끼워넣었다가 엔티티 불일치로 오류. Child 전용 `Prepare`로 옮기려 했는데, Child는 `lock dependent by`라서 애초에 `Prepare` 자체가 Root(`lock master`)에만 허용되는 것이었음. 결국 Prepare 없이 `on save`만으로 유지하기로 함 — 경고는 남지만 정상 동작.

### `get_instance_authorizations` 방치 문제
Draft + Managed 조합에서는 이게 비어있으면 권한 자체가 안 열린다고 해서 내용을 채워보려 했는데, `%action-Activate`가 존재하지 않는 컴포넌트라는 에러가 남. 결국 안의 내용은 그냥 비운 채로 유지.

### Projection BDEF — Create 버튼이 계속 안 뜨는 문제
위 항목들을 다 고쳐도 Create 버튼이 여전히 안 떴음.

🐛 원인: Projection BDEF(`ZC_B07_EINA`)에 `use action Edit/Activate/Discard/Resume`이 아예 없었음. CRUD(`use create/update/delete`)는 열어놨지만 Draft 액션 자체를 노출 안 해서 Draft 초기화가 안 되고 있었던 것.

액션을 추가했는데도 또 오류가 나서, `use association _Eine { create; with draft; }` / `use association _Eina { with draft; }`도 추가해보고, 에디터 왼쪽에 MARA를 띄워두고 한 줄씩 비교하며 뜯어봐도 문법적으로는 전혀 문제가 없는 상태까지 갔는데도 계속 오류가 발생했음. 빠진 것도 없고 오류 메시지도 더 이상 도움이 안 되는 상황이라, 파일 자체가 손상된 상태로 남아있을 가능성이 있다고 판단.

✅ 해결: Projection Behavior Definition 파일을 삭제했다가 다시 만듦. 아무 코드도 입력하지 않았는데 원하던 정석 코드가 바로 제안되는 걸 확인.

관련 오브젝트: [`ZC_B07_EINA`](../../reference/05_purchase-info.md) BDEF · [코드 보기](../../src/05_purchase-info/bdef/ZC_B07_EINA.bdef.asbdef)
```abap
projection;
strict ( 2 );
use draft;

define behavior for ZC_B07_EINA //alias <alias_name>
{
  use create;
  use update;
  use delete;

  use action Edit;
  use action Activate;
  use action Resume;
  use action Discard;
  use action Prepare;

  use association _Eine { create; with draft; }
}

define behavior for ZC_B07_EINE //alias <alias_name>
{
  use update;
  use delete;

  use association _Eina { with draft; }
}
```

앞으로는 Root 쪽을 먼저 다 구현하고 나서 Projection을 만드는 게 좋겠다는 걸 깨달음.

🧪 테스트: 빈 값으로 Create를 눌러봤을 때 기본단위/자재/공급업체 관련 값은 잡히는 것을 확인. 다만 나머지 Validation(CheckRequired/CheckDuplicate/CheckEsokz/CheckExist/CheckPositive 등)은 하나씩 확인해보지 못함.
