### 서치헬프 우선 적용 — FS 5.2 요구사항 범위
FS 5.2에 "구매단위, 공급업체, 자재는 Value Help(Search Help) 적용"이라고 명시되어 있고, 셋 다 이미 서치헬프 자체는 만들어져 있었음(`ZI_B07_MEINS_F4`/`ZI_B07_LIFNR_F4`/`ZI_B07_MATNR_F4`). Projection에 연결만 하면 됨.

관련 오브젝트: [`ZC_B07_EINA`](../../reference/05_purchase-info.md) · [코드 보기](../../src/05_purchase-info/cds/ZC_B07_EINA.ddls.asddls)
```abap
// 공급업체
@Consumption.valueHelpDefinition: [{ entity: { name: 'ZI_B07_LIFNR_F4', element: 'Lifnr' } }]
Lifnr,

// 자재
@Consumption.valueHelpDefinition: [{ entity: { name: 'ZI_B07_MATNR_F4', element: 'Matnr' } }]
Matnr,

// 구매단위 — 필드명(Meins)과 서치헬프 element명(Msehi)이 다른 케이스라 주의
@Consumption.valueHelpDefinition: [{ entity: { name: 'ZI_B07_MEINS_F4', element: 'Msehi' } }]
Meins,
```
화면에서 셋 다 정상적으로 F4가 뜨는 것 확인.

Lifnr/Matnr는 텍스트(Liftx/Maktx)를 hidden 처리하지 않고 별도로 노출해뒀기 때문에, 서치헬프로 값을 선택했을 때 텍스트가 함께 채워지는 Determination과, 저장 시점에 코드-텍스트 값이 서로 다르지 않은지 확인하는 Validation이 추가로 필요하다는 걸 확인함 — 오늘은 서치헬프 연결까지만 하고 이 둘은 TODO로 남김.

### Loekz(구매정보 취소) — 서치헬프 불필요, 대신 Feature Control 필요
MDE에서 `Loekz`를 "구매정보 취소"로 라벨링해뒀는데, 값이 플래그(`X`/공란)라 RAP가 자동으로 체크박스로 렌더링해줌 — 서치헬프 자체가 필요 없는 필드였음.

🐛 (FS 요구사항은 아니고 자체 판단) 설계상 "구매정보 취소"는 생성 시점엔 의미가 없고 Edit 때(혹은 삭제하려다 취소하는 용도)만 쓰여야 함 → 생성 시 readonly 처리하는 Feature Control 추가 구현이 필요해 보임. 오늘은 TODO로만 남기고 아직 구현 안 함.

### 구매정보내역(Irtxt) — 자유 텍스트 + 편의용 서치헬프
메모 성격의 필드라 아무 값이나 입력 가능해야 하지만, 자주 쓰는 문구를 고르기 편하게 서치헬프만 얹기로 결정. Validation은 의도적으로 만들지 않음(목록에 없는 말도 자유롭게 적을 수 있어야 한다는 원래 설계 의도 유지).

- Domain Fixed Value + Value Help: 사용자 편의 기능
- Validation 미생성: 자유 텍스트라는 설계 의도 유지

이를 위해 신규 Data Element(`zeb07irtxt`)/Domain(`ZDB07IRTXT`, FV 11건)을 만들고, 테이블 필드도 `txz01`(표준 필드) 대신 `irtxt`로 교체하기로 함.

```
1순위 업체
긴급 발주 전용
백업 업체(2순위)
연간 단가계약 적용
분기별 가격 재협상
품질우수(저불량)
납기 준수율 양호
신규 업체(시범중)
최소구매수량 주의
성수기 지연
단종 예정(소진용)
특정 프로젝트 전용
```
(도메인 FV가 char 10까지만 허용되어 최초 문구 목록에서 길이를 줄인 최종본. 처음엔 11개로 셌는데 최종은 12개.)

DO/DE 생성 및 활성화 후, 참조 순서(Consumer 쪽부터 역순: BDEF Mapping → MDE → Projection → Root → Interface → Table)로 주석을 하나씩 풀어야 했는데 잘 안 돼서 한 번에 몰아서 Activate — 정상 처리됨.

관련 오브젝트: [`ZTB07EINA`](../../reference/05_purchase-info.md) · [코드 보기](../../src/05_purchase-info/tables/ZTB07EINA.tabl.asddls)
```abap

```
[`ZI_B07_EINA`](../../reference/05_purchase-info.md) · [코드 보기](../../src/05_purchase-info/cds/ZI_B07_EINA.ddls.asddls)
```abap

```

### 구매조직(Ekorg)/구매그룹(Ekgrp) 서치헬프 신규 생성
기존까지 만들어놓은 서치헬프가 없어서 신규 생성 — 이번 작업의 포인트로 잡은 "추가" 필드.

**구매조직 (`T024E`)**: 하드코딩 없이 실데이터로 구성하고 싶어서, 표준 컨피그 테이블 `T024E`(구매조직)/`T024E_ASSIGN`(구매조직-회사코드 매핑)에 SM30(`V_T024E`, `V_T024E_ASSIGN`)으로 직접 데이터 입력(구매조직 `1000` "Basic Purchasing Org", 회사코드 `K200`과 매핑). 전체 공용 마스터 테이블에 데이터를 넣은 셈이라 팀 공용 TR(`Organization Structure Configuration`)로 저장.

`T024E`는 텍스트(`Ekotx`)와 회사코드(`Bukrs`)를 동시에 text.element로 띄울 수 없어서, `concat_with_space`로 회사코드+텍스트를 합친 `CombinedText` 컬럼을 별도로 만들어 우회. 회사코드가 비어있는 로우(`0002`)는 `CombinedText`가 콤마만 찍혀서 나오는 문제가 있어 `where bukrs <> ''`로 제외.

관련 오브젝트: [`ZI_B07_EKORG_F4`](../../reference/00_common-searchhelp.md) · [코드 보기](../../src/00_common-searchhelp/cds/ZI_B07_EKORG_F4.ddls.asddls)
```abap
@ObjectModel.text.element: ['CombinedText']
@UI.textArrangement: #TEXT_FIRST
key ekorg as Ekorg,
    @UI.hidden: true
    ekotx as Ekotx,
    @UI.hidden: true
    bukrs as Bukrs,
    @Semantics.text: true
    concat_with_space( concat( bukrs, ','), ekotx, 1 ) as CombinedText
```

**구매그룹 (`T024`)**: 데이터 프리뷰로 확인해보니 회사코드/구매조직 어디에도 연결되지 않은 독립 마스터였고, 이미 데이터가 3건 있어서 그대로 사용. 필드도 풍부해서(연락처/팩스/이메일 등) 드롭다운·concat 없이 전체 필드 그대로 노출.

관련 오브젝트: [`ZI_B07_EKGRP_F4`](../../reference/00_common-searchhelp.md) · [코드 보기](../../src/00_common-searchhelp/cds/ZI_B07_EKGRP_F4.ddls.asddls)

### 구매그룹(Ekgrp) F4 팝업 미동작 트러블슈팅 (미해결)
구매조직(Ekorg) F4는 정상 동작하는데, 구매그룹(Ekgrp) F4 아이콘을 클릭해도 팝업/드롭다운이 아예 열리지 않음(클릭 무반응).

가설 검증 과정:
1. CDS View 내 UI/Search Annotation 누락 — Annotation 추가 후 Activate해도 동일 → 기각
2. 원천 데이터(T024) 부재 — SE16N으로 3건 존재 확인 → 기각
3. Dropdown 용량 설정(`sizeCategory`) 문제 — `#XS` 추가해도 무반응 → 기각
4. CDS View 자체 실행/권한/타입 에러 — Data Preview(F8)로 3건 정상 출력 확인 → 기각
5. Projection/MDE 설정 오류 — 정상 동작하는 Ekorg와 동일 구조로 선언되어 있고 UI를 막는 Annotation 없음 → 기각
6. BDEF/구현 클래스의 Feature Control 비활성화 — `Ekgrp`에 readonly 지정이나 Dynamic Feature Control 자체가 없음 → 기각
7. `additionalBinding` 명시적 보강 — 추가해도 무반응 지속 → 기각
8. Service Definition 미노출(`expose`) — RAP 특성상 `@Consumption.valueHelpDefinition` 선언만으로 자동 암묵 노출되는 것 확인(다른 F4 뷰들도 expose 없이 정상 동작) → 기각
9. SAP Gateway 메타데이터 캐시 꼬임 — `/IWFND/CACHE_CLEANUP`/`/IWBEP/CACHE_CLEANUP`으로 전체 캐시 삭제 후 시크릿 창으로 재검증 → **여전히 미동작**

9가지 가설을 다 확인했는데도 원인 미확정. 코드/구조 문제는 아닌 것으로 보이며 OData Metadata Engine 쪽 문제로 추정되나, 몇 시간을 썼음에도 해결 못 함 — 내일 이어서 재검증하기로 하고 우선 다음으로 넘어감.

## cf. 참고 개념
- `@Consumption.valueHelpDefinition`이 CDS 뷰에 선언되어 있으면, Service Definition에 별도로 `expose`하지 않아도 OData가 암묵적으로 노출해준다(Implicit Exposure).
- 도메인 Fixed Value는 char 10까지만 허용됨 — 텍스트 문구를 FV로 관리할 땐 길이 제약을 미리 감안해야 함.
